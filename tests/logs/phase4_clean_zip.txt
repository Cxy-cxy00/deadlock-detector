  3) export wait-for graph เป็นภาพ
==================================================================

   $ DD_DOT_OUT=cycle.dot LD_PRELOAD=./build/libdetect.so ./build/bank

     digraph deadlock {
       rankdir=LR;
       labelloc=t;
       label="DEADLOCK: 2 threads in cycle";
       node [fontname=monospace];
       edge [fontname=monospace, fontsize=10];
     
       T0 [shape=ellipse, style=filled, fillcolor=mistyrose, label="Thread 544"];
       M0 [shape=box, style=filled, fillcolor=lightblue, label="mutex 0x56fe09e4c030"];
       T1 [shape=ellipse, style=filled, fillcolor=mistyrose, label="Thread 543"];
       M1 [shape=box, style=filled, fillcolor=lightblue, label="mutex 0x56fe09e4c070"];
     
       T0 -> M0 [color=red, label=waiting];
       M0 -> T1 [label="held by"];
       T1 -> M1 [color=red, label=waiting];
       M1 -> T0 [label="held by"];
     }

   [ผ่าน]     ได้ไฟล์ cycle.dot และไม่ว่าง
   -> เขียน cycle.png แล้ว เปิดดูได้เลย

   วงรี = thread  สี่เหลี่ยม = mutex
   T -> M คือกำลังขอ (แดง)   M -> T คือถูกถืออยู่
   ลูกศรวนครบรอบ = circular wait  ตรงกับ resource allocation graph ในสไลด์

  4) เวอร์ชันที่แก้แล้ว — ล็อกตามลำดับสากล

   $ LD_PRELOAD=./build/libdetect.so ./build/no_deadlock

no_deadlock: บัญชีเดียวกับ bank.c แต่ล็อกตามลำดับสากล (id)
             ต้องจบเองภายใน ~2 วินาที และเครื่องมือต้องไม่รายงานอะไร

[t1] โอน alice -> bob 10 รอบ
[t2] โอน bob -> alice 10 รอบ
[t1] done
[t2] done

ยอดคงเหลือ: alice=2000 bob=0 (รวม 2000)
ใช้เวลา 2002 ms (ต้องไม่น้อยกว่า 1500 ms = 3 คาบของ detector)
PASS: จบเองไม่ค้าง ยอดรวมถูกต้อง และรันนานพอให้ detector ตรวจหลายคาบ

   ^ บัญชีเดียวกัน โอนสวนทางกันเหมือนกัน
     ต่างแค่ทุก thread ล็อกตามลำดับสากลเดียวกัน
   [ผ่าน]     จบเองไม่ค้าง (exit 0)
   [ผ่าน]     ไม่มี [DEADLOCK DETECTED] (ไม่เตือนผิด)
