Deadlock Detector

เครื่องมือหา deadlock ในโปรแกรม multithread โดยไม่ต้องแก้โค้ดของโปรแกรมนั้นเลย

ภาษา CLinux LD_PRELOADpthread บท Deadlocksความยาก 3.5 / 5

1ปัญหาคืออะไร

โปรแกรมหลาย thread ที่ล็อกสลับลำดับกัน จะค้างทั้งโปรแกรมโดยไม่มี error อะไรออกมาเลย

ต่างคนต่างถือของที่อีกฝ่ายต้องการ ไม่มีใครยอมปล่อย

อาการที่เห็นคือ โปรแกรมเงียบไปเฉย ๆ ไม่ crash ไม่มี error CPU เป็น 0% ต้องเดาเองว่าค้างตรงไหน

2เครื่องมือของเราทำอะไร

รันโปรแกรมผ่านเครื่องมือ แล้วมันบอกเลยว่า thread ไหนรออะไร ใครถืออยู่ และผิดที่บรรทัดไหน

$ ./bank                                 # ค้าง ไม่มีอะไรบอก
^C

$ LD_PRELOAD=./libdetect.so ./bank       # รันผ่านเครื่องมือของเรา

ใช้กับของจริงได้

ใช้กับโปรแกรมที่คนอื่นเขียนได้ทันที

บอกบรรทัดที่ผิด

ชี้ไปที่บรรทัดใน source ได้เลย

3มันแทรกตัวอยู่ตรงไหน

เราวางตัวคั่นระหว่างโปรแกรมกับ library ของระบบ ทุกการล็อกจึงวิ่งผ่านเราก่อน

ตัวแปร LD_PRELOAD สั่งให้ dynamic linker โหลด library ของเราก่อน ฟังก์ชันชื่อเดียวกันของเราจึงถูกเรียกแทน

4ตรวจเจอได้อย่างไร

สร้าง wait-for graph แล้วหา cycle — ตรงตามทฤษฎีในบท Deadlocks

ถ้า DFS เจอ cycle แปลว่าเกิด deadlock แล้ว
เวลาเกิดอะไรตารางของเรา
t0T1 ล็อก A ได้holder[A] = T1
t1T2 ล็อก B ได้holder[B] = T2
t2T1 ขอ B → ค้างedge T1 → T2
t3T2 ขอ A → ค้างedge T2 → T1
t3.5detector thread ตื่นมาตรวจเจอ cycle → พิมพ์รายงาน

T1 กับ T2 ค้างอยู่ทั้งคู่ แต่ detector เป็นคนละ thread จึงยังทำงานและรายงานออกมาได้

5Demo ตอนนำเสนอ

  1. รันโปรแกรมโอนเงินธรรมดา → ค้างเฉย ๆ ไม่มีอะไรบอก
  2. รันใหม่ด้วย LD_PRELOAD → รายงานออกมาพร้อมบรรทัดที่ผิด
  3. เปิดภาพ cycle ที่ export เป็น Graphviz
  4. แก้โค้ดให้ล็อกตามลำดับเดียวกัน → รันใหม่ ไม่มีรายงานแล้ว
  5. รันกับโปรแกรมที่ไม่ได้เขียนเอง เพื่อยืนยันว่าใช้กับของจริงได้
