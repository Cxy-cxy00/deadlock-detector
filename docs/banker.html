นายธนาคารมีเงินจำกัด ลูกค้าแต่ละคนแจ้ง "วงเงินสูงสุด" ไว้ล่วงหน้า

เวลามีคนมาขอเบิก นายธนาคารไม่ได้ถามแค่ว่า ตอนนี้เงินพอจ่ายไหม แต่ถามว่า:

ถ้าจ่ายก้อนนี้ไป ยังเหลือทางจ่ายให้ทุกคนครบเต็มวงเงินได้ทีละคนอยู่ไหม

ถ้ายังมีทาง = safe จ่ายได้ · ถ้าไม่เหลือทาง = unsafe ปฏิเสธ ให้รอไปก่อน แม้เงินในมือจะพอจ่ายก็ตาม

process = ลูกค้า · resource = เงิน · OS = นายธนาคาร
unsafe ไม่ได้แปลว่าค้างแล้ว แต่แปลว่า "อาจค้างถ้าทุกคนขอเต็มวงเงิน" — Banker's เป็นอัลกอริทึมแบบอนุรักษ์นิยม มันปฏิเสธคำขอที่จริง ๆ อาจไม่มีปัญหาก็ได้

1 ตั้งค่าระบบ

เลือกตัวอย่างสำเร็จรูป หรือแก้ตัวเลขในตารางเองได้เลย

Need = Max − Allocation (ขอเพิ่มได้อีกเท่าไหร่) · Available = Total − ผลรวม Allocation (ของว่างในระบบ)
ช่องพื้นเทาคำนวณให้อัตโนมัติ แก้ไม่ได้

2 ตรวจว่าสถานะนี้ปลอดภัยไหม

หา process ที่ของว่างพอจ่ายให้ครบ Need แล้วสมมติว่ามันทำงานจบและคืนของทั้งหมด วนแบบนี้จนครบทุกตัว

3 จำลองการขอทรัพยากร

หัวใจของ Banker's — ลองขอดูว่าได้หรือไม่ได้ และเพราะอะไร

คำขอที่ถูกปฏิเสธจะกลายเป็น "คำขอค้าง" (process นั้นรออยู่) แล้วโผล่เป็นลูกศรแดงในกราฟข้างล่าง
